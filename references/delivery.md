# 运行记录与验收

在项目输出目录保存 `run.json` 与 `delivery.md`，它们属于用户内容，不提交到本 Skill 的公开仓库。依赖已有产物无需搬动；记录真实路径即可。不要用空文件或占位链接凑齐交付。

## 运行记录最小字段

| 字段 | 内容 |
| --- | --- |
| `run_id` / `mode` | 本次标识，A／B／C |
| `source` | 实际源文路径或正文保存位置、版本哈希；贴图含有序来源清单 |
| `scope` | 用户要求的平台、草稿／仅素材／明确发布授权与排除项 |
| `cover_tasks` | 同轮登记的微信／X 任务、风格、提示词路径、状态、开始时间；串行退化时含原因 |
| `artifacts` | 每个文件的实际绝对路径、用途、图片实际像素、可复用来源 |
| `platforms` | 微信、X、小红书分别的素材状态、远端状态、草稿 ID／链接、回读或用户声明证据 |
| `missing` / `status` | 缺口、下一步、总状态 `completed/partial/blocked` |

每个平台的素材状态与远端状态独立记录。远端状态使用 `not_requested`、`pending`、`created_unverified`、`verified`、`published`、`blocked` 或 `unknown`；`published` 须另存证据来源 `verified/user_reported`。只读过用户声明时不标为独立验证。

## 逐项检查

- [ ] 源文事实与改写一致，未捏造数据或亲历，原稿保留。
- [ ] A／双平台 C 的微信、X 封面任务从首次规划起都存在；两份提示词在对应生图之前落盘。并发可用时两路同轮提交，无法并发有记录。
- [ ] 微信母版 2010×600、横版 1410×600、方版 600×600 的实际像素与裁切坐标正确；分别查看三张图。左右标题与主体完整、无跨缝依赖、无裁切标记；X 独立构图并符合指定比例。
- [ ] 有排版时，Markdown、干净 HTML、复制预览和发布信息齐全；标题、≤120 字符摘要、封面单独展示；依赖校验为 0 ERROR／0 WARNING。标清是否只完成结构检查。
- [ ] X 是原生文章文稿，不含公众号 HTML 样式和专属互动口令，使用独立 X 封面。
- [ ] B 的图片顺序可追溯、无误裁；推荐标题≤20字（含标点）、正文与原图相符，标签 5–10 个。调用标题公式 Skill 时候选保留编号。
- [ ] 远端草稿 ID／链接来自真实响应，封面已附上；回读不足就明确标记。公众号前置条件满足后才写 X。
- [ ] 三端均有一行状态；未要求的平台写 `not_requested`。C 全部远端写入为 `not_requested`；A 未要求小红书时也如此。
- [ ] 无 AppSecret、token、Cookie、内部账号配置或虚构 URL 进入交付文件。

## 面向用户的交付格式

先写结果为“完成／部分完成／阻断”，再列一张表：

| 平台 | 本地产物（真实路径） | 远端状态与证据 | 缺口／下一步 |
| --- | --- | --- | --- |
| 公众号 | 本次实际文件 | 草稿 ID／已发布声明／未请求 | 具体缺口，或无 |
| X | 本次实际文件 | 文章草稿 ID／未请求／阻断 | 具体缺口，或无 |
| 小红书 | 本次实际文件或未请求 | 仅素材／明确授权后发布 | 具体缺口，或无 |

A／C 展示微信母版与 X 封面路径，附“上传母版后，横版选左侧，方版选右侧”；B 展示可复制标题、正文、标签和图片顺序。`delivery.md` 中保留完整路径清单与 `run.json` 位置。

完成只指本次约定范围：本地素材齐全但要求的草稿未建或未验收，整体是 `partial`；用户只要本地素材且素材通过，可为 `completed`。任何草稿状态都不能汇总成“已公开发布”。
