# 草稿推送与重跑

本文件规定写入边界和验收，不封装另一套客户端。执行前查看当前工具 schema、CLI `--help` 和需要时的官方文档，不能猜命令、参数或返回字段。只有已配置的合法凭据与用户选定账号可用；账号不明确时先保存本地并询问目标，不尝试其它账号。

## 公众号先完成

- [ ] 用户仅要求本地素材或仅封面：记录 `not_requested`，不连接远端。
- [ ] 用户已发公众号：保留其提供的文章链接或明确声明，记 `published` 与 `verified/user_reported`；不重复建稿。缺少链接不否定用户明确声明，但不能写成已独立验证。
- [ ] 其余 A 模式的分发请求：用当前安全配置检查公众号目标和草稿权限；不打印认证响应。
- [ ] 文颜 CLI 可用时先查它的版本及帮助，核实命令确实写**草稿**。名字叫 `publish` 的命令也不能凭名称猜测行为；若无法证明只建草稿，跳过该路径。
- [ ] 直接 API 时按官方流程上传正文图片和永久封面素材，取得真实媒体引用后调用 `POST /cgi-bin/draft/add`。`thumb_media_id` 必须来自本次已核实媒体或可追溯的既有媒体，不填本地路径、占位值或虚构 ID。封面裁切能力按当前接口文档设置；无该能力时在交付中保留裁切说明，不能声称已验证后台选区。
- [ ] 不调用 `freepublish/submit`、群发接口或其它公开发布路径；推稿请求不包含公开发布授权。
- [ ] 保存返回的真实草稿 ID，再使用当前草稿读取能力（例如官方 `draft/get`）核对标题、正文、正文图和封面引用；能查看预览时检查实际图片。只拿到 ID 未回读，标记 `created_unverified`，不能报已验收。

HTML 手动复制版与 API 上传版可能使用不同图片引用：手动版保留可携带图片，API 版由工具上传正文图并替换为平台可访问地址。保留两者，不覆盖可编辑原稿。媒体上传失败不得默默丢图继续建稿。

## X 后建文章草稿

- [ ] 先检查运行记录里的公众号前置条件：草稿已回读验收，或用户已明确告知已发布；否则仅保存 X 本地文稿和封面。用户明确另行允许跳过前置条件时记录该授权。
- [ ] 从当前工具清单发现已连接 X 插件的 `article_create_draft` 并读 schema；没有此工具就标记 `blocked`，不改用普通发帖、Thread、浏览器登录或自写未知接口。
- [ ] 按 schema 准备 X Articles 标题、原生正文与真实 X 封面。需要上传媒体时先使用该插件允许的媒体工具，取得真实封面引用；不能把本地路径当作公开 URL，也不能用微信母版代替 X 封面。
- [ ] 创建文章草稿，保存真实 draft ID／编辑链接和可公开的返回摘要；移除响应中的凭据。没有返回链接就不编造链接。
- [ ] 若有读取能力，回读标题、正文与封面引用；若工具只返回创建回执，记录 `created_unverified` 与“已返回草稿 ID，内容未回读”。不得将草稿创建等同于发布。

## 小红书发布是独立授权

默认只产出可发布素材；包括“仅自己可见”在内的发布都有远端副作用，不能作为自动预览步骤。只有用户明确要求“发布到小红书”才调用所选依赖的发布能力；公开可见须有明确的公开授权。保存可核对的笔记 ID／链接与可见性，调用失败不宣称已发。

## 重跑与故障停止条件

运行记录以 `源文版本＋目标账号＋平台` 识别同一稿件，保存既有 draft ID。源文用本地哈希识别，不把源文内容或本地路径发送到无关服务。

| 情况 | 处理 |
| --- | --- |
| 本地生成／只读查询失败 | 仅失败项可重试一次；保留已成功产物 |
| 认证／权限失败 | 停止该远端分支，报告具体缺口，不轮换账号／身份 |
| 创建草稿超时、响应丢失 | 标记 `unknown`，先查已有 ID／草稿列表与本次运行证据，不能直接重试创建 |
| 草稿已存在且内容一致 | 复用 ID，不重复创建 |
| 草稿已存在但内容变化 | 保存新本地版本，明确当前请求是否包含更新草稿；未授权更新则只交付差异 |
| 无法确认远端是否已创建 | 保持 `unknown`，交付本地稿，列出需要用户核实的账号和标题 |

重试不绕过公众号→X 的顺序，也不把 `unknown` 改成“未创建”后重新提交。草稿列表／回读请求同样只使用已授权账号。
